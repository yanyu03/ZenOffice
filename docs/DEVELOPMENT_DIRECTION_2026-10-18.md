# ZenOffice 新开发方向

日期：2026-10-18。状态：接管后的工作基线；后续方向改变需记录理由和验收影响。

## 产品目标

先交付 Windows 本地优先的 Sheets Alpha：用户打开支持的XLSX，看到能力与限制，修改已有数字输入，重算，撤销/重做，另存，重开后得到一致结果。CSV新建与导出作为辅助流程。遇到不能安全维护的内容给出明确原因，并保持原件与旧输出。

第一版不承诺任意Office文件兼容、完整Word论文排版、全部Excel函数或全对象PPT编辑。Word和Slides保留受控命令行能力。

## 仓库与来源

为GitHub公开仓库创建独立的干净源码目录 ZenOffice。zen-office-v2原工程、历史证据与冻结样本保留，不递归移动或清理。首批迁入核心Rust crates、受控交付入口、相关测试与项目自制固定样本；记录源文件哈希和迁入修改。

旧UI原型、WPS图标和派生资源、逆向材料、Office运行输出、外部论文模板、工具链及缓存不进入公开首次提交。这不是删除成果：公开基线先包含能明确界定的引擎范围；旧前端可在脱离WPS资源、具备来源声明后单独迁入。

## 主线与验收门

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| M0 版本与复现 | Git基线、准确README、依赖锁定、公开文件清单、来源说明、构建脚本 | 干净克隆可构建CLI并执行默认测试；外部测试显式标记；提交与报告可对应 |
| M1 应用服务 | 抽出与CLI共用的打开、准入、编辑、撤销、重算、保存服务；源状态重查 | 数值修改、依赖重算、撤销重做、另存重开端到端通过；锁定/不支持/源变化均保留数据 |
| M2 单一桌面入口 | 接入M1，同步显示能力诊断与未保存状态 | 原生桌面实测完整流程，键盘操作与大表可视区域可用；无WPS安装也可运行 |
| M3 Sheets Alpha候选 | 多份独立业务样本、安装包与恢复说明 | 冻结提交上的Rust回归、Excel同等修改对照、失败保护、连续编辑保存和UI验收均通过 |
| M4 扩展编辑 | 文本/公式输入、更多函数与依赖 | 每项有独立语义、缓存、拒绝边界与同等输入的宿主对照；不按函数名称计完成度 |

阶段按退出条件推进，不承诺没有证据支持的交付日期。公开仓库建成与M0全部通过是两件事；认证成功不等于产品验收。

## UI路线

不再同时推进三套前端。已有ADR选择Qt Widgets，暂保留为M2候选，不在本轮再次换框架或宣称Qt已交付。进入M2前先在干净环境完成不依赖WPS资源的Qt构建、启动与服务桥接小样；固定CMake依赖版本、移除本机SDK路径假设、补来源与分发说明。若此门无法合理通过，再写ADR比较egui，之后只迁入一种前端。

首个界面只做工作表、公式栏、打开、另存、撤销、重做、错误提示；自主设计视觉与图标。原有WPS布局复刻不作为验收目标。

## Word专项的收束

当前断行差异保留为W-001：横向字体度量与balanceSingleByteDoubleByteWidth解释不足。首轮最多做一组字体/字号/普通空格/制表后空格的边界对照；随后必须提交以下之一：

- 有明确支持范围的真实字宽接口、兼容字段实现、回归与原生断行对照；
- 说明仍未知的行为，将预览标为近似并登记阻断条件，回归Sheets主线。

不改原文件兼容设置来制造通过，不把120twips写成全局空格常量，不把近似预览升级为完整论文排版承诺。重复表头、跨页表格、TOC/REF更新排在主线Alpha之后，除非出现已支持保存路径的数据损失。

## 每次开发的交付规则

每次只选一个有可见结果的任务。提交包含问题、变更、针对性检查、未测范围与下一步；实现变更后才补对应验收。安全保存失败优先于新功能；确认稳定后不反复全套运行。外部宿主测试单列，不通过修改预期或静默跳过掩盖失败。历史自动化仍指向旧工程，本轮没有擅自修改或恢复其调度，迁移时需明确唯一写入目录。
