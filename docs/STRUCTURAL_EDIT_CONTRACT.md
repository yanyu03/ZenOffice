# ENG-006结构编辑与引用计划契约

日期：2026-10-23。性质：可变实施设计，落实ZEN-ENGINE-v1.0 ENG-006，不替代冻结条件。前置ENG-005实况042有界DONE、9cfa54e原生/回归证据已核对。当前源码基线9cfa54e；本轮仅纯坐标计划器，完整结构编辑未实现、未运行Office。

## 源码现况与复用边界

- workbook.rs的SheetId为文档内非零稳定身份；CellAddress为零基坐标，界限1048576行×16384列。Worksheet/Workbook读取模型、包保持器及会话不可变帧仍可复用。
- calc.rs::CellReference只有sheet/col/row；recalc.rs::Expr/Token用于计算，不保留源跨度、引用固定标记或所有原词法。reference_or_name经CellCoord解码后构造CellReference。计算AST不能作为保真公式编辑树，也不能从计算结果反推原$标记。
- spreadsheet/edit.rs当前补丁针对已有显式单元格及变化缓存；安全保存、候选重读、历史预算与undo/redo已由ENG005验收，但没有新表、重命名、行列结构或填充的工作簿事务接口。
- 当前受限recalc支持SUMIF（同形区域，禁止隐式扩大）；条件统计的其余需求、查找与日期/文本函数要按后续3业务计划逐项设计。旧UI/legacy evaluator的函数名不是保包WorkbookCalculator已经支持的证据。

## 首个代码切片：已解码单点坐标

reference_plan.rs新增ReferenceAnchor{SheetId,CellAddress,row_fixed,column_fixed}、AxisEditPlan和copy_anchor。轴操作的构造校验非空、范围内区间；map_anchor只映射显式目标SheetId上的点；map_anchors按调用方明确的anchor数量预算一次返回完整结果，任何后项越界/分配失败不给部分向量，输入不改。

预先约定engine_specs/ENG-006-reference-plan-v1.json：插入使位置及以后引用点位移，固定标记不阻止结构位移；删除区间内点返回Deleted，区间后点前移，其他SheetId不动。复制偏移只影响相对维度，保留固定标记和显式sheet身份；隐式本表绑定由未来公式上下文解析，不由此模块猜测。以上为本实现的坐标政策，尚未用原生Excel结构操作对照。

Deleted不是写出#REF!的授权；范围不能通过独立映射两端点来声称正确处理截断/扩展；整个轴删除仅有坐标数学结果，不是有效工作簿操作准入。全工作簿扫描、词法解析、重算、候选包与提交均未接入。模块没有I/O、Env开关、公式字符串入口或隐藏写路径。数量预算不是完整堆内存/工作簿预算，分配失败分支未注入实测。

## 统一引用编辑计划的后续合同

未来结构请求至少携带原帧完整身份/revision、稳定SheetId、操作（新表/重命名/行列插删/复制填充/基础数值格式）及显式参数和预算。生成计划不是提交权限：原帧变化则拒绝，禁止将旧坐标计划套到新帧。

1. 先扫描全部可能的引用拥有者，建立按部件/源码跨度的编辑清单，不能只扫当前表的c/f。至少包括跨表公式、范围、定义名称、图表、calcChain、工作簿关系，以及dimension、row/c地址、列宽/行高、合并、条件格式、数据验证、表/筛选、打印区域、绘图锚点、超链接/外链、透视与其他扩展。
2. 词法/语法树须保留原文本跨度、$行列标记、字符串字面量、带引号/单引号转义的sheet名及是否显式限定；通过稳定SheetId解析引用绑定。禁止正则全局替换表名/数字；字符串中看似A1的内容不能被误改。已有计算AST继续用于计算，不兼任文本写回。
3. 单点映射复用本轮planner；范围采用单独的插入扩张/删除裁剪/全失效政策并做独立预期+原生对照。混合/全固定引用在插删与复制中分别验证。名称、3D、结构化表引用、数组/共享/data-table、动态/外部引用在未建完整计划前拒绝；首个结构写切片可保守拒绝所有定义名称，不能继承既有值编辑的名称准入就宣称结构安全。
4. 新表/重命名需独立名称/身份/关系分配策略及转义，新建不复用已删除身份；重命名不改变SheetId。名称长度/非法字符/大小写冲突规则须显式准入并取证，当前模型最小校验不等于Excel完整命名规则。删除表及跨簿移动暂不隐含加入范围。
5. 行列插删同时规划单元格与相关元数据；越出网格、碰到未处理依赖、删除引用会需要尚未支持的错误序列化时先拒绝。不得静默丢弃尾部数据、截断坐标或伪造可计算#REF!。复制填充须明确源/目标重叠、相对基点、绝对/相对/混合引用及跨表上下文；先构造完整候选，不能逐格写到一半。
6. 基础数值格式不是给c/s随便换索引：需显式格式范围、合法styles拥有关系/xf、去重/分配/继承及保留政策；不把样式保留当作新格式创建或显示正确。日期格式依旧遵守体系与序号规则，区域渲染另验收。
7. 计划全部通过才补丁写候选；重新从候选文本建立依赖图并重算支持结果，核对每个缓存与原calcPr政策，再按原limits重读。预算与revision/历史提交沿用session，不绕过失败原子性、撤销/重做和create-new保存。
8. 旧opaqueXML policy只证明当时声明范围的显式保留前提；结构变更可能改变语义独立假设。不能以旧值编辑通过或本轮坐标数学通过自动授权未知部件参与结构改写，必须重新审查操作相关依赖；无法证明则拒绝。
